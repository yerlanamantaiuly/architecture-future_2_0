# Карта рисков трансформации

Шкала вероятности и влияния: **низкая / средняя / высокая**. Оценка — на старте трансформации (as-is: монолитный DWH + Camel, SQL Server 2008, смешанные мед- и финданные).

## Архитектурные

| ID | Риск | Вероятность | Влияние | Почему актуален |
|----|------|-------------|---------|-----------------|
| A1 | DWH остаётся скрытой системой записи, домены пишут «и в события, и в таблицы» | высокая | высокое | Привычная модель 15+ лет; dual-write даёт расхождения KPI |
| A2 | Событийная шина повторяет Camel: общее ядро, тотальная связанность через payload | высокая | высокое | Без schema governance Kafka станет ESB с топиками |
| A3 | Медицинские данные протекут в витрину «для удобства отчёта» | средняя | высокое | Давление бизнеса на полный срез пациента; регуляторный удар |
| A4 | Нет единой идентичности `party_id` / согласия — клиент клиники и банка не стыкуются или стыкуются слишком жёстко | средняя | высокое | Купленный банк и клиники жили раздельно |
| A5 | Геораспределение без доменных границ: ПДн региона в общем озере | средняя | высокое | Цель «2–3 новых региона» на горизонте 3 лет |
| A6 | Потоковые витрины и batch DWH считают разные цифры (два источника правды) | высокая | среднее | Неизбежно на этапе 6–18 месяцев |

## Организационные

| ID | Риск | Вероятность | Влияние | Почему актуален |
|----|------|-------------|---------|-----------------|
| O1 | Домены не принимают владение data product (всё снова на «команде DWH») | высокая | высокое | Data Mesh ломается без Data Product Owner |
| O2 | Сопротивление клиник отказу от PowerBuilder | средняя | среднее | Операторы заточены под текущий UI |
| O3 | Нехватка компетенций: Kafka, stream processing, cloud IAM | высокая | высокое | Стек сегодня — SQL, Power BI, Camel, Python-скрипты |
| O4 | Банк и клиники не договариваются о приоритетах бэклога платформы | средняя | высокое | Разные KPI и лицензии |
| O5 | Партнёры фармы/медтеха подключаются через «ещё один маршрут Camel» в обход платформы | средняя | среднее | Быстрее для продаж, дороже для архитектуры |

## Технологические

| ID | Риск | Вероятность | Влияние | Почему актуален |
|----|------|-------------|---------|-----------------|
| T1 | SQL Server 2008: потеря поддержки, уязвимости, невозможность масштабировать сотни ТБ | высокая | высокое | Уже as-is |
| T2 | Нестабильный CDC / поломанные схемы при миграции | средняя | высокое | Легаси-схемы «живые», без документации |
| T3 | Простой Kafka / schema registry останавливает клинику и банк одновременно | низкая | высокое | Шина — новая единая точка отказа, если нет мульти-AZ |
| T4 | Раздувание cloud-счёта (hot storage снимков, бесконечный retention топиков) | средняя | среднее | Объёмы «сотни ТБ», imaging особенно |
| T5 | Vendor lock-in в PaaS (управляемый Kafka, OLAP, IAM) | средняя | среднее | Ускоряет пилот, бьёт на горизонте 3 лет |
| T6 | Power BI-кастомизации не переносятся на семантический слой портала | средняя | среднее | Годы отчётов поверх DWH |
